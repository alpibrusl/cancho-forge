Authority is a property of the runtime

  
Prompts ask agents to behave. Forge makes the misbehaviour impossible to express, and says so in a report you can read.

  

    
📒
One journal
Every objective, task, attempt, approval and cost is an append-only record. Recovery cuts only a torn last line and refuses, changing nothing, on a corrupt complete one.

    
🔒
Narrowed capabilities
A worker gets an Exec bound to its own programs. Going outside the bound is a trap, so the policy layer refuses first and journals why.

    
🧾
Evidence, not claims
A worker's "success" is an assertion. Acceptance needs checks Forge ran itself, tied to the artifact they ran on.

    
🧱
Pure cancho
No Python, Rust or shell in the product. cancho authority prints what each program can reach.

165 → 140bytes: a torn journal tail is cut, and a second recovery changes nothing

    
5 / 5worker endings classified: normal, failed, garbage, exit 3, hang

    
82 / 82tests pass under cancho test (journal record, task state machine, journal replay, snapshots, the CLI's text), and 62 / 62 file cases of the two conformance programs

    
25crash points: a writer killed with child_kill_group after each step of append, sync, snapshot and rename, then recovered; 420 checks, 0 failed

Linux x86_64 only, one compiler revision (pinned in cancho.toml), a mock worker. The 82 tests, 62 file cases and 25 crash points are Milestone 1's core, added after the spikes (a process kill leaves the page cache, so none of them tests power loss). Not measured: macOS, a real Cancho Code run with a model (its interface was audited against a stand-in agent, docs/cancho-code-audit.md), several workers at once, power loss. What the spike found missing

  
Written down before any of it is built around.

  

    
Grants fixed at build time
narrow takes literals, so a per-task bound cannot be chosen at run time.

    
Grants fixed at build time, bounds that trap
Filed upstream as cancho #534 and #535, both open. A worker's subprocesses used to survive a kill; cancho #533 (child_kill_group) fixed that and the spike now passes with no /bin/kill in the Exec bound.

    
Contract is provisional
The real Cancho Code interface has not been audited yet, so forge-worker/1 will change in M2.

  






  
Ask your coding agent to try it

  
Paste this into Claude Code, Codex or any coding agent that can run commands. It installs the pinned compiler, proves the install with the gate (no network, no key, no model), and runs the spikes that produced the numbers above.

  

    
prompt raw

    
Install cancho-forge and check it on this machine. Work in a new empty directory, keep every path free of spaces, and never use sudo. Run steps 2 to 5 in one shell session. Report honestly; do not retry a failing command in a loop and do not edit the repository to make a command pass.

1. Check that `git`, `cargo` (Rust, via rustup), a C compiler (`cc`), `clang` and `sh` exist. If one is missing, stop and tell me which; do not install system packages on your own.

2. Get the two repositories side by side, both cloned into the new empty directory (call it the parent):
   git clone https://github.com/alpibrusl/cancho-forge.git
   git clone https://github.com/alpibrusl/cancho.git
   git -C cancho checkout "$(cat cancho-forge/.cancho-rev)"

3. Build the compiler (a few minutes) and point at it:
   (cd cancho && cargo build --release -p cancho)
   export CANCHO="$PWD/cancho/target/release/cancho"

4. Prove the install works. This needs no network, no key and no model. Start from the parent directory:
   cd cancho-forge
   sh scripts/gate.sh        # must end with: gate: PASS
   The gate runs `cancho fmt --check`, `cancho check`, `cancho test`, two file conformance programs, a kill-at-every-crash-point program, the `forge` CLI cases, the authority report and a 2,000-line file budget.

5. Run the Milestone 0 spikes. They start real child processes and write under /tmp/cancho-forge-spike (about 15 seconds):
   sh spike/run.sh
   Read the output. Find these in it and show me the lines:
   - the five ways a worker can end (`normal`, `reports fail`, `garbage`, `exit 3`, `hang`) and how each was classified;
   - the journal lines: the torn tail being cut (`file_bytes=165` then `140`), and `REFUSED: complete line(s) that are not the next event; file left untouched`;
   - `lock by second writer (must fail): FAILED errno 11`.

6. Tell me, briefly:
   - whether the gate printed `gate: PASS`, and how many tests it ran;
   - the lines asked for in step 5;
   - anything that failed, with the exact error.
Nothing here runs a company yet: this is Milestone 0 and the first part of Milestone 1. Docs: README.md, spike/RESULTS.md (what was measured), docs/cancho-code-audit.md (the real interface of cancho-code), docs/architecture.md.
