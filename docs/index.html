An agent company you can audit.

cancho-forge keeps state, budgets, approvals and evidence in the runtime, so a worker cannot mark its own work accepted or grant itself authority.

A real run of the Milestone 0 spike. A worker that says "succeeded" only reaches verification; the runtime, not the worker, decides what is accepted. The dispatcher can run one directory of programs and cannot read a file.

Authority is a property of the runtime

Prompts ask agents to behave. Forge makes the misbehaviour impossible to express, and says so in a report you can read.

📒

One journal

Every objective, task, attempt, approval and cost is an append-only record. Recovery cuts only a torn last line and refuses, changing nothing, on a corrupt complete one.

🔒

Narrowed capabilities

A worker gets an Exec bound to its own programs. Going outside the bound is a trap, so the policy layer refuses first and journals why.

🧾

Evidence, not claims

A worker's "success" is an assertion. Acceptance needs checks Forge ran itself, tied to the artifact they ran on.

🧱

Pure cancho

No Python, Rust or shell in the product. cancho authority prints what each program can reach.

Measured, at Milestone 0

Seven spikes ask whether cancho can carry a runtime like this. Each number is from a run you can repeat.

Linux x86_64 only, one compiler revision (pinned in cancho.toml), a mock worker. Not measured: macOS, a real Cancho Code, several workers at once, power loss. Commands and verbatim output: spike/RESULTS.md.

What the spike found missing

Written down before any of it is built around.

Grants fixed at build time

narrow takes literals, so a per-task bound cannot be chosen at run time.

A kill reaches one pid

A worker's own subprocesses survive it. A process-group kill works, but widens the Exec bound.

Contract is provisional

The real Cancho Code interface has not been audited yet, so forge-worker/1 will change in M2.
